\subsection{Data Extraction in PRISM}

The dataset used in this study originates from the \textit{Plastics Recovery Insights Steering Model (PRISM)}, a platform created by AEPW that combines plastic waste, demographic, and socioeconomic data from various public sources into a usable format.

\begin{figure}[H]
	\centering
	\includegraphics[width=1.0\linewidth]{figures/prism_data_extraction.png}
	\caption{
		PRISM data extraction workflow. The system first identifies the input document type (either PDF or tabular file). For PDF documents, PRISM uses \texttt{PyMuPDF} to parse text regions and extract layout elements, and processes images to recover text, tables, and figures using large language models (LLMs). Parsed content is then chunked, indexed, and processed through evidence-grounded extraction using LLMs with retrieval-augmented generation (RAG) and Chain-of-Thought (CoT) reasoning. Subsequently, the extracted data undergo schema enforcement and human validation before being used in downstream analysis.
	}
	\label{fig:prism_data_extraction}
\end{figure}

Figure~\ref{fig:prism_data_extraction} illustrates the data extraction workflow used by the PRISM platform to transform unstructured documents such as PDF or Excel files. The workflow consists of separate parsers utilized based on the input document type. Layout elements such as images, charts, and tables are interpreted using GPT-4o to produce meaningful context. PDF files are parsed using the \texttt{PyMuPDF} library, and on the other hand, Excel files are read in using the \textbf{Pandas} library.

After parsing, the PDF pipeline stores embedded text chunks in Azure AI Search to support retrieval-augmented generation for selected fields such as publisher and report date. Then, large language models are applied to identify relevant data points, including year, location, data point name, value, unit, and source context. Subsequently, the extracted outputs are passed through multiple post-processing layers, including data cleaning, location and data-point mapping, duplicate removal, unit standardization, calculated field generation, and quality score computation. Finally, the structured extraction results are appended to the database.

Because automated extraction with LLMs can be inaccurate, all extracted records are manually reviewed and approved before being migrated into the AUDA analytical database, where they are used for modeling and visualization.
