\subsection{Experimental Setup}

The experiments were run on a DigitalOcean Droplet with two AMD virtual CPU cores at 2.00 GHz and 4 GiB of memory. The operating system was Debian GNU/Linux 13.4 (trixie), using Linux kernel 6.12.43. All models were trained and evaluated on CPU without GPU acceleration.

For each experiment, 90\% of the available samples were used for training, and the remaining 10\% were held out for testing, with at least two samples reserved for the test set. For forecasting experiments, we used chronological splits without shuffling, so the held-out test samples came from the end of the time series. For reconstruction experiments, we used random splits with seed-controlled shuffling, while keeping the first and last samples in the training set so interpolation-style reconstruction had boundary points to work from.

To mitigate experimental bias arising from different random seeds, each experiment is repeated 16 times. To ensure reproducibility, the seeds used in these repeated runs are deterministically derived from a master seed.

During hyperparameter tuning, forecasting models used expanding-window time-series cross-validation with \(K = 4\) validation folds. The ordered training data were split into \(K + 1\) contiguous blocks; the first block served as the initial training window, and each later block was used once as the validation window after training on all previous blocks. Reconstruction models used repeated random holdout validation with five masks, each reserving 20\% of the training samples, with at least two validation samples, and used the remaining samples for fitting.

For reproducibility, most experiments use a fixed base seed of 471. The metrics reported in the tables are averaged over 16 runs with different sampled seeds to reduce dependence on any single train-test split. In contrast, each plot shows one representative run; for these figures, we selected a seed that produced behavior consistent with the averaged results.
