\subsection{Experimental Setup}

All experiments were run on a DigitalOcean Droplet with two AMD virtual CPU cores at 2.00 GHz and 4 GiB of memory. The operating system was Debian GNU/Linux 13.4 (trixie), using Linux kernel 6.12.43. All models were trained and evaluated on CPUs without GPU acceleration. All experiments were conducted using Python 3.12.11 with NumPy 2.4.4, pandas 3.0.3, scikit-learn 1.8.0, statsmodels 0.14.6, PyTorch 2.11.0, and Matplotlib 3.10.8.

For predictive experiments, 90\% of the samples in the dataset were used for training, and the remaining 10\% were held out for testing, with at least two samples reserved for the test set.
For the univariate temporal forecasting experiments, chronological splits were used without shuffling, so the test samples came from the end of each time series.
For the pooled neural-network experiment, samples were shuffled before the train--test split because the pooled country-year records do not form a single time series.
For imputation experiments, the data were shuffled and split randomly, while keeping the first and last samples in the training set so that interpolation-style imputation models could work on boundary samples.

For ridge regression, Gaussian process regression, and support vector regression, predictors and targets were standardized using parameters fitted separately within the corresponding training fold or partition only. ARIMA and exponential-smoothing models were fitted on the original scale. In the neural-network experiment, rural population, urban population, and GDP were transformed using \(\log(1+x)\) before standardization; targets were also standardized. The isolation forest was fitted only on the predictor variables from the training partition, and the outer test set was not used during preprocessing, hyperparameter selection, or early stopping.

During hyperparameter tuning, forecasting models used time-series cross-validation with \(K = 4\) validation folds. The ordered training data were split into \(K + 1\) blocks, with the first one serving as the initial training window. Each subsequent block was used once as the validation window after training on all previous blocks. Imputation models used repeated random holdout validation with five masks, each reserving 20\% of the training samples, with at least two validation samples, while using the remaining samples for fitting.

All random processes are controlled by a seed for reproducibility. To reduce dependence on any single random split, each reported predictive experiment was repeated 16 times; the run seeds were deterministically generated by NumPy's \texttt{default\_rng} from master seed 471. The tables report averages over the 16 runs. Each figure shows the fixed run specified for that figure in the reproducibility scripts, rather than a subjectively selected representative run.
